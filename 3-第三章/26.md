**语言与函数的交互式证明**

复杂性理论家通常喜欢研究判定问题（decision problems），即值域为 $\{0,1\}$ 的函数 $f$。我们将判定问题视为“是-否问题”，具体方式如下：对 $f$ 的任何输入 $x$ 都被解释为一个问题，即：“$f(x)$ 等于 1 吗？”。等价地，我们可以将任何判定问题 $f$ 与由 $f$ 的“是-实例（yes-instances）”组成的子集 $L \subseteq \{0,1\}^n$ 关联起来。任何子集 $L \subseteq \{0,1\}^n$ 都被称为一个**语言（Language）**。

针对语言的 IP 的形式化定义与函数的形式化定义（定义 3.1）略有不同。我们简要描述这种差异，因为复杂性理论中关于 IP 及其变体威力的著名结果（例如 $\text{IP} = \text{PSPACE}$ 和 $\text{MIP} = \text{NEXP}$）指的就是针对语言的 IP。

在针对语言 $L$ 的交互式证明中，给定公共输入 $x \in \{0,1\}^n$，验证者 $V$ 与证明者 $P$ 交互的方式与定义 3.1 完全相同，并且在协议结束时 $V$ 必须输出 0 或 1，其中 1 对应“接受”，0 对应“拒绝”。针对语言 $L$ 的 IP 的标准要求是：

- **完备性（Completeness）**：对于任何 $x \in L$，都存在某种证明者策略，能使验证者以高概率接受。
- **可靠性（Soundness）**：对于任何 $x \notin L$，对于每一个证明者策略，验证者都会以高概率拒绝。

给定一个语言 $L$，设 $f_L : \{0,1\}^n \to \{0,1\}$ 为对应的判定问题，即如果 $x$ 在 $L$ 中，则 $f_L(x) = 1$，如果 $x$ 不在 $L$ 中，则 $f_L(x) = 0$。请注意，对于 $x \notin L$，上述针对 $L$ 的 IP 定义并不要求存在一个“令人信服的证明”来证明 $f_L(x) = 0$ 这一事实。这与针对函数 $f_L$ 的 IP 定义（定义 3.1）形成了对比，定义 3.1 的完备性要求对于每一个输入 $x$（甚至包括那些 $f_L(x) = 0$ 的输入），都必须存在一个证明者策略能够说服验证者关于 $f(x)$ 的具体数值。

> (31)一个重要的注意事项是，在本综述第 11-17 章所考虑的大多数零知识证明与论证中，证明者（prover）将是随机化的（randomized）。证明的这种随机化对协议的完备性或可靠性没有影响，其引入的纯粹目的是确保证明不会向验证者泄露任何信息（除了证明本身的有效性之外）。
